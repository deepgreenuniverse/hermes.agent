# hermes.agent

AI Agent 编程规范 / Behavioral Guidelines for AI Coding Agents

---

## 背景

hermes.agent 起源于日常与 AI 结对编程时踩过的坑：

- AI 反复问同一个已确认的问题（上下文丢失）
- 改动范围蔓延到需求之外（过度设计）
- 危险操作没确认就执行（数据丢失风险）
- 重构后服务起不来（验证缺失）

这些问题的根源不是 AI 能力不足，而是 **行为规范缺失**。

---

## 核心理念

以 [Andrej Karpathy 的 LLM 编码准则](https://github.com/forrestchang/andrej-karpathy-skills) 为基础，结合真实踩坑经验迭代。

核心：**谨慎优于速度**。对于简单任务自行判断；对于复杂/不可逆操作，必须确认。

---

## 规范体系

| 编号 | 规范 | 解决的问题 |
|------|------|------------|
| 1 | 动手前先想 | 假设导致的方向错误 |
| 2 | 简洁优先 | 过度设计、代码膨胀 |
| 3 | 精准改动 | 改动蔓延、破坏性重构 |
| 4 | 目标驱动执行 | 验收标准模糊、循环返工 |
| 5 | 上下文感知 | 反复确认已确认的信息 |
| 6 | 变更即验证 | 代码上线后才发现问题 |
| 7 | 危险操作确认 | 不可逆操作导致数据丢失 |
